# iEtsh LMD Analytics — Power BI

This folder contains the real Power BI data-query and DAX layer. It is separate
from the Excel dashboard currently embedded on the website.

## Data source

Power BI reads the existing generated workbook:

`exports/iEtsh_LMD_Analytics.xlsx`

The workbook is regenerated by the existing GitHub Actions workflow from the
Supabase tables `lmd_puzzles` and `lmd_puzzle_snapshots`. No Supabase service
key is placed in Power BI or in the public website.

## Build in Power BI Desktop

1. Open Power BI Desktop and create a blank report.
2. Open **Transform data > New Source > Blank Query > Advanced Editor**.
3. Copy each of the three query definitions from `PowerQuery.pq` into its own
   query, naming them exactly:
   - `PuzzleMasterData`
   - `ObservationLog`
   - `PuzzleTrends`
4. In Power Query, create a date-only column in ObservationLog:
   `Snapshot Date = Date.From([captured_at])`
   Set it to type **Date** and apply changes.
5. Create a Date table with this DAX calculated table:

```dax
Date =
VAR MinDate = MINX ( ObservationLog, ObservationLog[Snapshot Date] )
VAR MaxDate = TODAY ()
RETURN
ADDCOLUMNS (
    CALENDAR ( MinDate, MaxDate ),
    "Year", YEAR ( [Date] ),
    "Month", FORMAT ( [Date], "MMM" ),
    "Year Month", FORMAT ( [Date], "YYYY-MM" ),
    "Month Sort", YEAR ( [Date] ) * 100 + MONTH ( [Date] )
)
```

6. Mark `Date` as the Date table using `Date[Date]`.
7. Create relationships:
   - `PuzzleMasterData[lmd_code]` (one) → `ObservationLog[lmd_code]` (many)
   - `PuzzleMasterData[lmd_code]` (one) → `PuzzleTrends[lmd_code]` (many)
   - `Date[Date]` (one) → `ObservationLog[Snapshot Date]` (many)
   Use single-direction filtering from the one side.
8. Add the measures from `Measures.dax`.

## Suggested report pages

### 1. Overview
- KPI cards: Active Puzzles, Combined Solves, Average Rating, Average Difficulty.
- Historical Combined Solves as a line chart by Date[Date], with LMD and
  SudokuPad historical series as separate lines.
- Top 10 puzzles by Combined Solves.
- LMD vs SudokuPad share.
- Slicers for publication year and difficulty.

### 2. Puzzle Performance
- Puzzle title, publication date, difficulty, rating, LMD solves,
  SudokuPad solves, and combined solves.
- Scatter plot: difficulty vs combined solves.
- Platform comparison by puzzle.
- Top/bottom ranking with a puzzle selector.

### 3. Growth & History
- Historical LMD Solves and Historical SudokuPad Solves by date.
- Combined Change by date.
- Snapshot count and selected-puzzle trend.
- A note that historical totals begin when a puzzle first receives a saved
  observation; the sync process records changed tracked metrics, not every run.

### 4. Data Quality
- Rating and difficulty coverage.
- Missing-value counts.
- Current puzzle count versus observed puzzle count.
- Latest observation date.

## Refresh and publishing

The source workbook is public because the website's existing Excel analytics
page is public. Power BI therefore imports public puzzle analytics only.
After the report is built, save the PBIX and publish it to the Power BI Service.

The final website embed URL is not available until you publish the report.
Only then can the website's Power BI tab be wired to the exact report URL.
Do not use **Publish to web** for private or sensitive information: it makes
the report publicly accessible to anyone who obtains the URL.

The website password gate is only a user-interface gate. It does not secure
the published Power BI report itself.
